可以。你现在这套「浮脂溯源」已经证明了最难的一条链：

**网页 → 图文块 → Vision 读地区 → 官方地图候选 → Point 绑定 → 人审 → 本地 Guide → Viewer**

下一步不应该为每一种谜题重新写一套爬虫和 Matcher，而是把它升级成一个**通用 Guide Atlas Engine（全地图攻略引擎）**。

我看了这次 `submit.zip`，现在已经有 `regions/`、`vision/`、`matching/`、Review、Dedup、Guide DB、Viewer Guide API 等基础，所以这次应当是“泛化现有架构”，而不是推倒重来。

# 总目标

最终系统应自动回答两个问题：

```text
① HoYo 全地图里的哪些内容真正需要攻略？

② 对于每一个需要攻略的目标：
   网上是否存在图文攻略？
   图和文字分别在讲什么？
   对应官方地图里的哪个 Point / 哪组 Point？
```

```text
官方地图

社区图文攻略
```

# 一、第一原则：不是“5330 个 Point 全都做攻略”

这一点必须先定死。

你的官方数据现在有：

```text
5330 Points
1006 selectable labels
624 maps
```

但绝大多数不值得制作图文攻略。

例如：

```text
界域定锚
普通商店
普通敌人
绝大多数阅读物
普通显眼战利品
```

只需要地图位置即可。

真正需要攻略的，是几类内容：

| 类型             | 是否需要攻略  | 典型内容            |
| -------------- | ------- | --------------- |
| **机关解谜**       | 强需要     | 浮脂、迷钟、磁流解阈、不世之材 |
| **操作挑战**       | 强需要     | 二次元 JUMP、小小哈努   |
| **隐藏获取**       | 需要      | 隐性战利品、特殊宝箱      |
| **全收集**        | 需要路线型攻略 | 折纸小鸟、若虫、尘灵      |
| **特殊交互**       | 通常需要    | 扎格列斯之手、奇迹宝珠     |
| **特殊敌人/奖励**    | 视情况     | 王下一桶、次元扑满       |
| **普通宝箱**       | 通常不需要步骤 | 只显示坐标           |
| **普通敌人/商店/锚点** | 不需要     | 地图本身足够          |
| **阅读物**        | 通常只需位置  | 可做全收集，不做逐点解谜    |

所以第一步不是爬网，而是建立：

> **Guide Requirement Registry**

# 三、Guide Scope 必须扩展

你现在几乎默认：

```text
1 Guide
→
1 source_point_id
```

浮脂适合。

全地图以后不够。

正式定义：

```text
POINT
POINT_SET
MAP_LABEL
MAP
REGION
GLOBAL
```

### POINT

一个攻略对应一个 Point。

例如：

```text
浮脂 #1
梦境迷钟 #7
```

### POINT_SET

一个解谜由多个官方点共同组成。

例如可能出现：

```text
机关本体
操作台
奖励
```

应该是一个 Guide Target，不是三个攻略。

### MAP_LABEL

一篇攻略覆盖：

```text
海原市所有折纸小鸟
```

例如：

```text
1 篇路线攻略
→
该地图 12 个 Point
```

### MAP

整张图攻略。

例如：

```text
本地图所有隐藏宝箱
```

### REGION

例如：

```text
匹诺康尼全区域折纸小鸟
```

### GLOBAL

机制教程：

```text
二次元 JUMP 玩法说明
```

以后可能所有 Point 共用。
