# 攻略完整性逻辑层（guide completeness）

用户 2026-10 指示：判断一份攻略完不完整，要看**玩家拿到这个点位要走到哪一步**，
而不是看「有没有攻略」。逻辑层把这件事变成可计算的判定（`hsrmap/guides/stages.py`，不依赖模型）：
两个正交维度、三种证据能力、六个状态。

## 一、两个维度

| 维度 | 取值 | 含义 |
| --- | --- | --- |
| 完成要求 `completion_requirement` | `LOCATE_ONLY` | 走到地图点就能拿到（若虫、折纸鸟、尘灵的位置） |
| | `LOCATE_AND_SOLVE` | 到了还要做事（触发、方向序列、模块解谜、平台路线、挑战） |
| 解法类型 `solve_kind` | `NONE` / `INTERACT` / `INPUT_SEQUENCE` / `MODULE_PUZZLE` / `TRANSFORM_ROUTE` / `PLATFORM_ROUTE` / `CHALLENGE` / `OTHER` | 要做事的话，是哪一种事 |

要求写在主题档案里（`hsrmap/guides/topics/profiles/*.yaml` 的 `completion:` 块），
**点位级证据可以上调**：主题默认 `LOCATE_ONLY`，但某个点的官方说明写
「完成此处「黄金替罪羊」解谜获得。」，这个点就变成 `LOCATE_AND_SOLVE`——
这正是用户举的例子（`point_requirement()`，依据标注为 `point` 还是 `topic`）。

## 二、三种证据能力

一份攻略不必三种都提供，逻辑层分开记账：

| 能力 | 意思 | 典型来源 |
| --- | --- | --- |
| `SCOPE` | 「该地图共 N 个」——知道总数，不知道是哪一个 | 范围条目（`set:` / `map:` / `global:` 键） |
| `LOCATE` | 能不能到点 | 官方点位截图、一行「位于…」、带方位的路线文字 |
| `SOLVE` | 到了之后怎么做 | 方向序列、模块步骤、触发方式 |

范围条目的正文说的是整张地图（「该地图共 260 个若虫」），所以除非它带图，
**范围条目本身不算 LOCATE 证据**。

## 三、六个状态（没有百分比）

| 状态 | 含义 |
| --- | --- |
| `NO_EVIDENCE` | 什么都没有 |
| `SCOPE_ONLY` | 只有范围证据，点位级证据还没有 |
| `LOCATE_MISSING` | 知道怎么做 / 有多少，但不知道是哪一个、在哪儿 |
| `LOCATE_COMPLETE` | 「到点即得」的点位：定位证据已齐（**第 1 阶段完成**） |
| `SOLVE_MISSING` | 位置有了、缺解法（**第 1 阶段完成，第 2 阶段缺**） |
| `COMPLETE` | 「到了还要解」的点位：定位 + 解法都齐（**第 2 阶段完成**） |

两种「已完成」：`LOCATE_COMPLETE` 是到点即得的终点，`COMPLETE` 是还要解的点位的终点；
`is_done()` 把两者都算完成，但报告里分列，读者一眼能看出「为什么它算完成」。

**状态的输入是「已发布的攻略」+ 官方点位本身**：

- `LOCATE` 以官方为准（用户 2026-10 指示：「对于第 1 阶段的，采用官方点位就可以了，
  一切以官方为标准，官方没有再补充」）。报告本来就是遍历官方点位生成的，所以
  `official_point=True`：**点位出现在官方地图上，就等于玩家能照着官方地图走到它**。
  官方数据是最终版，没有「再等官方补一张图」这回事。
- `SOLVE` 仍然只看已发布攻略里的步骤（方向序列、模块步骤、触发方式）——这是唯一还在缺的东西。
- 范围条目不构成 LOCATE 证据（`set:`/map: 的正文说的是整张地图有多少个）；
  点位配对只认完全相等的 id 或 `set:` 里的完整 id（`LIKE '%388%'` 曾让 3388 的攻略算成 388 的）。

于是六状态在官方点位上收敛成三个：`LOCATE_COMPLETE`（到点即得）/ `SOLVE_MISSING` /
`COMPLETE`；`NO_EVIDENCE`、`SCOPE_ONLY`、`LOCATE_MISSING` 只在没有官方点位的数据里才可能出现。
**缺口只剩 SOLVE。**

## 六、下游怎么用

0. **结案**：一个目标查过、确实没有公开来源时，用
   `guides no-public-source --topic X --apply` 把它记成 `NO_PUBLIC_SOURCE_FOUND`。
   它只承认证据账本里真有的搜索（至少一次、且没有任何 ACCEPTED 候选），并要求该目标没有已发布攻略、
   没有挂着的评审；判定连同查询写进 `source_search_verdict`，账本随即改口。
   这一条是「缺源收敛」的正规出口——不是把数字做好看，而是把「查过了，没有」变成可复核的记录。
1. **找源**：`guides search-plan --topic X` 的缺口现在来自 `completion_gaps()`
   （缺 `LOCATE` / 缺 `SOLVE` / 都没有），查询家族随之分化——
   `query_families(..., missing="SOLVE")` 只问解法，`missing="LOCATE"` 只问位置。
   账本缺口（`NEEDS_SOURCE`）仍然并进来，负责完成模型看不到的 MAP_LABEL 目标。
2. **官方点位图**：对 `LOCATE_ONLY` 点位就是**最完整的攻略**（官方截图 + 一行说明 = `LOCATE` 齐），
   不是兜底。`guides official-seed --all --apply` 按点位补发，与社区攻略走同一条发布与审计通道。
3. **看进度**：`guides completeness --markdown`（主题汇总表）、
   `guides completeness --missing solve|locate|any`（直接给工作队列，现在两张队列都是空的）、
   `guides closure-check` 的记分板也带上完成模型——`Ready to grab 1006 / 1006`、
   `Missing solve 0`、`Missing locate 0`，覆盖率按**点位口径**报，账本标签口径另列一行。

## 六之二、官方点位条目也在审计范围里

`Published audit` 原本只有一条规则：每个步骤都要在**它自己声明的来源网页**里找得到，
找不到就是 `UNGROUNDED_STEP`。官方点位条目没有网页（`source_url` 是官方图片），
于是 478 条官方攻略一律被记成「缺来源页 + 步骤无出处」，把真实问题（18 条）淹没了。

现在审计按来源种类分流：`source_kind = Official` 的条目，用**官方点位说明**（`detail.db`
的 `plain_text`）作为正文做同一套 grounding 检查——官方说明里有的步骤算落地，凭空写的
仍然算 `HALLUCINATED_STEP`；官方说明本身是空的（例如二次元 JUMP）则记 `DERIVED_LABEL`
（我们按地图名拼出来的标签），而不是假装它有出处。审计结果因此从
「495 条有问题」回到「18 条有问题」，其中 `HALLUCINATED_STEP = 0`。

## 八、图解法转录（2026-10）

判定层只读**文字**：一张长图里写着「解密步骤 1: 开局Q一下，再跳到中间平台的右上角…」，
机器看不见，点位就永远算缺解法。2026-10 起承认一类新证据：

```text
[图解法转录 <图片sha前8位>] <地图><N>号点位：第1步 …；第2步 …；…
```

- 前缀写明是哪张图，**那张图必须挂在这条条目（或同一来源页的条目）上**，否则仍然算幻觉步骤；
- 审计把它记成 `IMAGE_TRANSCRIBED_STEP`（有图可查的记录），而不是问题；
- 用「第N步」让 `has_solution_steps` 的序号模式稳定命中。

第一批 23 条转录让浮脂溯源 14 → **40 / 48** 完成；证据落盘在
`data/guides/reports/floating-grease-solve-worklist.json`（每条点位含候选条目、图片绝对路径、
图里是否有答案），剩下 8 个点位的社区条目是 0 图空壳，属于真缺来源。

## 七、历史：为什么不再是「三种结论」

逻辑层最初只给 `COMPLETE` / `IMAGE_WALKTHROUGH` / `LOCATION_ONLY` 三种结论，
但那个模型把两件事混在一起：**要求**（这个点位要不要解）和**证据**（这份攻略补上了什么）。
用户指出这不够用——「若虫的官方点位图」和「黄金替罪羊的解法」本来就该用不同标准衡量，
于是改成「要求 × 证据 → 六状态」。

仍然成立的一条观察：**米游社式长图里步骤是画在图上的**
（「解密步骤 1: 开局Q一下，再跳到中间平台的右上角 / 2: 之后从这里向右跳…」，
见 `data/guide-assets/sha256/00/0087f6d9…jpg`）。这类攻略在模型里仍是 `SOLVE_MISSING`
（图是 `LOCATE` 证据，不是机器可读的 `SOLVE` 证据），把长图读出来（OCR / 视觉转录）
一次可以让 120 个「缺解法」里的一批直接变 `COMPLETE`。
